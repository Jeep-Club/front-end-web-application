# InputPassword

Campo registrado com alternância de visibilidade e checklist opcional de senha. O schema continua responsável por aceitar ou rejeitar a senha.

## Uso com React Hook Form

```tsx
import { InputPassword } from '@/components/common/input/input-password';

// Dentro do Form do projeto, com schema e defaultValues correspondentes.
<InputPassword name="password" label="Senha" autoComplete="new-password" stepErrors />
```

Este componente exige FormProvider, como o fornecido por Form. Não possui modo `register=false`. Inicialize o valor como string em `formOptions.defaultValues` e use o mesmo `name` no schema. O erro exibido vem do React Hook Form. `required` sinaliza a obrigatoriedade; Form usa `noValidate`, por isso declare a regra no schema.

O nome legado padrão é `senha`. Use `autoComplete="current-password"` no login e `new-password` em criação/troca. `notSeePassword` oculta a ação de visibilidade. `disabled` também bloqueia essa ação. `stepErrors` mostra os critérios de `validPassword` e suprime a mensagem normal do campo; confira que os critérios correspondem ao schema do fluxo.

## Aparência e controles

A superfície acompanha os tokens de `data-theme`; alterne claro/escuro na toolbar. Não é necessário escolher variante de cor. `white`/`gray` permanecem por compatibilidade, como descrito em [Input](?path=/docs/componentes-input-input--docs). `className` e `labelClassName` ajustam o contexto. Os ícones não substituem o label.

## Integração e limites

As stories usam Form/RHF e Zod reais com validação mínima de campo preenchido, sem backend. Não representam todas as regras do domínio. Confira a integração e os estados de erro no [guia de Input](?path=/docs/componentes-input-input--docs). Os testes de navegador verificam o comportamento local; isso não certifica acessibilidade completa.
