# InputEmail

Campo registrado com ícone e tipo nativo email. A validação de formato e a obrigatoriedade pertencem ao schema.

## Uso com React Hook Form

```tsx
import { InputEmail } from '@/components/common/input/input-email';

// Dentro do Form do projeto, com schema e defaultValues correspondentes.
<InputEmail name="email" label="E-mail" autoComplete="email" />
```

Este componente exige FormProvider, como o fornecido por Form. Não possui modo `register=false`. Inicialize o valor como string em `formOptions.defaultValues` e use o mesmo `name` no schema. O erro exibido vem do React Hook Form. `required` sinaliza a obrigatoriedade; Form usa `noValidate`, por isso declare a regra no schema.

Passe `name` explicitamente: o valor legado padrão é `email;` (com ponto e vírgula). `type="email"` não faz uma consulta nem confirma que a caixa postal existe.

## Aparência e controles

`variant="white"` é o padrão, com superfície branca, borda cinza e texto escuro. `variant="gray"` mantém o campo cinza. `className` e `labelClassName` permitem compor o contexto. Os ícones não substituem o label.

## Integração e limites

As stories usam Form/RHF e Zod reais com validação mínima de campo preenchido, sem backend. Não representam todas as regras do domínio. Confira a integração e os estados de erro no [guia de Input](?path=/docs/componentes-input-input--docs). Os testes de navegador verificam o comportamento local; isso não certifica acessibilidade completa.
